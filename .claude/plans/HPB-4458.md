# HPB-4458 分批主版本迁移计划

> 每个 Batch 是一个独立 PR；批次串行推进，因为它们更新同一组 package.json / 锁文件。当前分支只执行当前未合并批次。

**Goal:** 以独立 PR 验证 Next.js 16/Contentlayer 兼容，并按依赖顺序逐批完成其余主版本迁移。

**Architecture:** Batch 1 保留 Contentlayer2 0.5.8 并让 Next 16 显式走 Webpack；之后分别升级 React/types、Vite/Vitest、ESLint/TypeScript。每个分支从最新 staging 创建，CI 全绿后再进入下一批。

**Tech Stack:** Next.js 16.4.4、Contentlayer2 0.5.8、React 18→19、Vite 7→8、Vitest 5、ESLint 9→10、TypeScript 5→7；Yarn Classic + npm 双锁文件。

**Spec:** docs/specs/2026-11-04-hpb-4458-next-contentlayer.md

## Global Constraints

- 每个迁移批次必须是独立 PR，分别跑测试、coverage、lint、类型检查、静态构建和仓库 CI 门禁。
- Batch 1 将 next、@next/bundle-analyzer、eslint-config-next 对齐到 16.4.4。
- Batch 1 暂留 React 18.3.1、@types/react 18、Vite 7、Vitest 5、ESLint 9、TypeScript 5.9。
- Batch 1 的 dev/start/build/analyze 必须显式包含 --webpack，避免 Next 16 默认 Turbopack 与 Contentlayer generated 冲突。
- Next 16 build 生成的 tsconfig jsx=react-jsx 与 next-env.d.ts 路由类型导入须保留，并由契约测试覆盖 jsx 运行时。
- Next 16.3+ 在 next dev 时生成的 AGENTS.md 托管区块纳入变更；不修改其余项目指引。
- eslint-config-next 16 的 flat config 需直接导入；react-hooks/set-state-in-effect 只在既有 MobileNav/ThemeSwitch hydration gates 上局部关闭。
- Yarn 与 npm 两份锁文件都要保留，锁文件更新限于本批 dependency graph。

## Review Focus

- Next 16 + Contentlayer generated：显式 Webpack 是否能完成生成和静态导出。
- Webpack flag 是否覆盖本仓库实际使用的 dev/start/build/analyze 脚本。
- Next 16 移除 next lint 后，ESLint CLI 是否使用 Next16 flat config，且不再经 FlatCompat 加载。
- Next16 React Hooks v7 是否引入额外规则；任何例外须限于已审查的 hydration gate 文件。
- React 18 是否满足 Next 16 peer；不得误将 types 提前升级。
- 锁文件更新是否无关漂移；后续分批保留各自 diff。
